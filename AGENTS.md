PROJECT RULES

1. Assignment PDF is the source of truth.
2. Never invent requirements.
3. Never claim something works without testing it.
4. Never fabricate test results.
5. Never fabricate API responses.
6. Never skip verification.
7. Never move to the next phase without explicit user approval.
8. Explain architectural decisions before implementing significant changes.
9. Preserve existing working code unless there is a demonstrated reason to change it.
10. Never expose secrets.
11. Prefer the simplest implementation satisfying the assignment.
12. RAG answers must be grounded in retrieved paper content.
13. If information isn't in the paper, say so.
14. Do not add out-of-scope features unless explicitly requested.
